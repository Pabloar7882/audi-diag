# ESP32 KW1281 — experimental

The board `esp32dev` is provisional. The ESP-IDF shell logs that it is waiting for hardware mapping and never configures GPIO, UART, a transceiver, networking, or vehicle output. No firmware has been flashed. Target build and real ECU compatibility remain unverified.

The portable C core permits only identify, keep-alive, and raw measurement groups 001, 003 and 011. It exposes no generic service, write, clear or EEPROM operation. A session starts zero-initialized with `fis_transport` callbacks assigned. Each operation receives an absolute monotonic millisecond deadline. All callbacks must themselves honor that deadline and return promptly on cancellation; the core checks the clock and cancellation before and after each call, but cannot interrupt a blocked callback. The transport must implement 5-baud initialization for engine address 0x01, the specified 25 ms keyword delay, and handling or suppression of local transmit echo. No target transport is provided.

The caller must serialize access to each session. A protocol, transport, timeout or cancellation failure invalidates the session and requires a fresh identify. Identity is a bounded sequence of seven-bit ASCII fields separated by newline; raw E7 data is returned without decoding or units. Responses are limited to 32 blocks per segment and 16 identity segments. Check lengths before consuming output; output is cleared on failure. Timing, electrical behavior, RAM/stack use, and physical traces require validation with the actual hardware.

## Catalog and sequential monitor contract

`fis_catalog_lookup()` exposes all 256 groups from the generated `fis_group_catalog.inc`, which is built from `data/sensor_catalog.v1.json`. Groups 001/003/011 are `FIS_CATALOG_ACTIVE_ALLOWED`; 197 other IDs with local label rows are `FIS_CATALOG_METADATA_ONLY`; 56 IDs without local rows are `FIS_CATALOG_UNKNOWN`. Candidate counts aggregate labels across ECU variants. The firmware carries no label archive, AFN field mapping, sensor decoder or formula, so group responses remain raw bytes. `fis_read_group()` enforces its separate fixed physical gate; catalog status or future label metadata cannot add query permission.

After changing `Labels/`, regenerate the shared JSON and C table with `py tools/build_sensor_catalog.py`, then rerun the native harness. The generated C table carries group status and aggregate row counts only; it does not carry label descriptions or values.

`fis_monitor` is an opt-in scheduling primitive, not a transport task. Initialize it with `fis_monitor_init()`, explicitly start it with a non-empty selection from 001/003/011 and a 500–60,000 ms minimum interval, then call `fis_monitor_next()` when the caller is ready to issue one request. The scheduler normalizes selected groups to 001 → 003 → 011, returns `FIS_BUSY` while a request is in flight, and returns `FIS_WAIT` until the selected group's minimum interval has elapsed since its previous successful completion. After the actual group request finishes, call `fis_monitor_complete()` with its completion timestamp and result. Any non-`FIS_OK` result suspends the monitor. `fis_monitor_stop()` disarms the next request immediately; if a transport callback is still in flight, the scheduler retains its reservation and rejects a restart with `FIS_BUSY` until `fis_monitor_complete()` acknowledges the return. A completion arriving after stop is discarded and returns `FIS_CANCELLED`. The owning transport must still honor cancellation for an operation already in progress. Starting an already-running monitor is rejected without resetting cadence.

The scheduler contains no timer, thread, UART, GPIO, Wi-Fi, screen, or retry logic. The application owns its explicit start/stop controls, waits, transport deadline, cancellation signal, and session recovery. Physical activation remains unvalidated.

Run `powershell -NoProfile -File firmware/esp32/scripts/test-native.ps1` from the project root using the specified Visual Studio MSVC installation. The build uses `/W4 /WX`. PlatformIO is pinned to `espressif32@8.0.0`; target dependencies belong under `.platformio` and a workspace-local `.venv`. Network refusal prevented installation/build.
